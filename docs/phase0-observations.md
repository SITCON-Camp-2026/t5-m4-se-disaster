# Phase 0 Observations

## 我們做出了什麼？

- 做出一個能從首頁進入的 Phase 0 前端工作台。
- 首頁可以看見 12 筆原始資訊、來源、查核狀態與更新時間。
- 整理工作台可以建立、查看、編輯、刪除與重設整理草稿；草稿仍標示為候選整理，不是已確認資料。

## 哪些資料讓 agent 很容易整理？

- 有明確時間、地點線索與現場回報語氣的資料，比較容易整理成候選大意。
- 有數量、限制與下一次盤點時間的資訊，看起來比較像可以被整理，但仍需要人工確認來源與適用時間。

## 哪些資料讓 agent 亂補或誤判？

- Agent 容易把「有人說」「群組說」補成確定來源。
- Agent 容易把模糊地點補成可派工地點。
- Agent 容易把「看起來像官方公告」當成已確認，但原文仍可能缺日期或同步狀態。

## 哪些資訊不能直接變成任務？

- 缺少完整地點、時間或當事人同意的資訊不能直接變成任務。
- 來源是轉述、留言或電話代述時，不能直接派志工行動。
- 有互相矛盾說法的資訊，需要先確認原因與最新狀態。

## 哪些資訊的操作者不是當事人？

- 由志工代長者轉述的資訊，需要確認當事人同意與完整需求。
- 由外地家屬來電轉述的資訊，需要先確認本人狀況與位置。
- 社群貼文或群組轉傳的資訊，不一定是當事人或現場窗口。

## 我們剛剛偷偷假設了什麼？

- 假設更新時間越新就一定比較可信，但來源與確認狀態仍然重要。
- 假設現場志工回報就可以直接行動，但仍可能缺正式同步或缺授權。
- 假設地名線索足夠派工，但原文可能不足以讓下一位協作者安全抵達或判斷。

## 如果要讓這個工具變可靠，下一步需要什麼？

- 需要更清楚的確認角色與確認流程。
- 需要區分原文、agent 建議、人類修正與已確認資訊。
- 需要讓每個候選整理都能追溯到原文依據。

## 我們需要更清楚資料格式的地方

- 來源類型不等於查核狀態，需要分開顯示。
- 需要欄位記錄資訊是否為當事人、轉述者或現場窗口提供。
- 需要欄位記錄缺少哪些資訊，例如時間、地點、數量、同意或負責窗口。

## 我們需要人工確認的地方

- 未查核或需要人工確認的資料不能被顯示成已確認。
- 操作者不是當事人的資訊，需要確認同意與需求。
- 看起來能派工的資訊，也需要確認是否仍有效、是否安全、是否有負責窗口。
